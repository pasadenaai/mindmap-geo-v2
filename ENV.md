# ENV.md — mindmap-geo

Local dev vars live in `.env.local`, which is **git-ignored** and generated per developer by `scripts/dev_env_init.sh` (random `SECRET_KEY`, mode 600) from `.env.local.example`.
Production vars go in `.env.aws` (never committed — use `.env.aws.template` as guide). In AWS, secrets come from Secrets Manager, not env vars.

## Secrets handling

- No credential-like literals in source or docs — enforced by `scripts/scan_secrets.sh` (gitleaks + pattern scan) and the `.pre-commit-config.yaml` gitleaks hook. Run `scripts/scan_secrets.sh` before every commit.
- Local: `scripts/dev_env_init.sh` creates `.env.local` (git-ignored, mode 600). `--force` rotates the generated values.
- AWS: secret `pai-mindmap-geo-v2/app` (KMS-encrypted at rest) holds `SECRET_KEY` (auto-generated by Secrets Manager) and `EIA_API_KEY` (set out-of-band). Only the Lambda role can read it (`secretsmanager:GetSecretValue`, single ARN).
- Rotation: rotate `EIA_API_KEY` at the provider, `put-secret-value`, then force new Lambda execution environments. Rotating `SECRET_KEY` invalidates all issued tokens.
- Deployment lockdown: the CDK stack refuses to synthesize without `--context allowed_ips=...` (no open-to-world default).
- Frontend transport: served from a **private** S3 bucket through API Gateway over HTTPS (TLS 1.2+, ACM cert on a Regional custom domain, WAF). No S3 website endpoint, no CloudFront. Not yet deployed.

## CDK context variables (`cdk deploy --context key=value`)

| Context key | Required | Description |
|---|---|---|
| `allowed_ips` | yes (fail closed) | Comma-separated CIDRs allowed through the API Gateway resource policy |
| `cert_arn` | for the custom domain | ACM certificate ARN (same account, us-east-1) for `domain_name`. Without it: no custom domain, CORS origins empty |
| `domain_name` | no | Site hostname; default `exploror.labs.pasadena.ai` |
| `data_removal` | no | `destroy` deletes DynamoDB tables, log groups and the assets bucket with the stack (first-deploy/throwaway only; default RETAIN). The app secret is always RETAINed because Secrets Manager reserves a deleted secret's name for 7-30 days |
| `api_access_logs` | no | `true` enables stage access logs to `/aws/apigateway/pai-mindmap-geo-v2-access`; only valid when the account-level API Gateway CloudWatch role is already set (owned by v1) |
